# P16.3 多项目账号生态互动关系矩阵方案

> 状态：代码更新完成，自动验收通过；真实 WOOD 保存与重编辑回显待用户操作
> 前置方案：`P16_2_whitelist_workspace_ui_convergence_proposal.md`

## 1. 问题定义

快速投研可能保留多个项目身份，例如项目官方、联合创始人、技术联合创始人和战略顾问。当前生态互动编辑器一次只能选择一个项目账号，再为该目标选择生态账号，存在三个问题：

1. 同一组生态账号需要对多个项目账号重复配置。
2. 用户无法直接表达“任意已选生态账号与任意已选项目账号互动均可触发”。
3. 关系数量、项目身份数量和 6551 Watch 数量混在一起，容易误判远端监控压力。

## 2. 业务语义

生态互动规则改为两个集合的关系矩阵：

```text
已选生态账号集合 A x 已选项目账号集合 T = 互动关系集合 R
```

示例：

```text
14 个生态账号 x 4 个项目账号 = 56 条互动关系
唯一 6551 Watch = 14 个生态账号
```

每条关系仍保持现有契约：

```json
{
  "actor_handle": "vladtenev",
  "target_x_handle": "sherwoodagent",
  "event_types": ["retweet", "quote", "reply", "follow"],
  "enabled": true
}
```

任一已选生态账号对任一已选项目账号发生已启用事件，即可匹配该白名单。是否再次成功买入继续由白名单的买入次数和预算控制，与关系数量无关。

## 3. 6551 资源模型

1. 6551 只 Watch 左侧 `actor_handle`。
2. 右侧 `target_x_handle` 只用于本地事件目标匹配，不创建远端 Watch。
3. Watch Impact 继续按 `actor_handle` 去重，关系从 14 条扩展到 56 条不会把 Watch 扩展到 56 个。
4. 相同生态账号已被其他白名单使用时继续复用同一个 Watch。
5. 关系矩阵增加的是少量本地关系行和索引查询；几十到数百条关系不构成当前系统容量压力。

## 4. 前端交互

### 4.1 双侧多选

生态互动编辑器改为：

```text
生态账号多选  ->  项目账号多选
```

两侧都支持：

1. 搜索。
2. 单项勾选和取消。
3. 全选当前结果。
4. 清空。
5. 完成后关闭浮层。

生态账号保留当前链、跨链、全部和未分类筛选；项目账号只显示当前白名单已经保留的项目身份以及编辑态历史互动目标。

两侧可以按任意顺序选择。仅选择一侧时保留可见草稿，但不生成无效关系；两侧均非空时立即生成完整关系矩阵，不再要求额外点击“添加关系”。手工输入生态账号仍作为补充入口，空值时禁用。

### 4.2 完整矩阵约束

1. 同一账号不能同时作为同一关系的生态账号和项目目标；出现交集时拒绝本次选择并明确提示。
2. 账号和目标统一去除 `@`、转为小写并去重。
3. 新关系继承当前关系事件集合。
4. 已存在的相同 actor-target 关系保留其 ID、Watch 状态和事件配置，不能因重新勾选丢失回显字段。
5. 编辑器只在用户改变两侧选择时重建矩阵；初次加载不得静默扩展历史非矩阵关系。
6. 关闭生态互动规则时清空关系矩阵和 `interaction_target`，但保留 `identity` 项目身份。

### 4.3 可扩展展示

禁止在主页面直接展开 56 条重复明细。主页面显示：

```text
14 个生态账号 x 4 个项目账号 = 56 条关系
14 个唯一 Watch
```

关系按项目账号分组，每个目标只占一行，显示关联生态账号数量和最多三个账号预览。事件复选框作为矩阵统一配置；修改后应用到全部矩阵关系。

### 4.4 确认保存

第 4 步继续显示：

1. 项目身份数量。
2. 生态互动关系数量。
3. 唯一 Watch 数量。
4. Watch 复用数量和新增数量。

保存仍通过现有 Outbox 同步；研究和草稿阶段不修改 6551。

## 5. 后端与兼容性

本次不修改 API、数据库和交易执行逻辑：

1. `x_signal_relations` 已使用 `(whitelist_id, kol_id, target_x_handle)` 唯一约束，原生支持多对多。
2. `normalizeRelationInputs` 已按 actor-target 去重并拒绝自关联。
3. `syncWhitelistRelations` 已支持批量插入、更新和删除完整关系集合。
4. Matcher 已按事件中的 `target_x_handles` 匹配目标关系。
5. Watch Impact 只聚合关系和来源中的 `actor_handle`。

编辑现有单目标白名单时，关系会自然回显为一个项目目标；多目标白名单回显为多个目标。历史非完整矩阵关系在用户主动修改选择前保持不变，并显示实际关系覆盖数。
