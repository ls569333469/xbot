# P16.2 白名单工作区前端收敛方案

> 状态：设计审查通过，正式 React 页面已实施并完成前端与相关契约验收；API、数据库和交易逻辑未修改
> 预览：`xbot-whitelist-workspace-v3-preview.html`

## 1. 问题结论

本轮问题不是单个 CSS 错位，而是新增能力进入页面后缺少统一的信息架构收口：

1. 左侧四步导航和右侧草稿进度表达同一件事，占用 428px 固定宽度，主表单反而成为最窄区域。
2. Grok 候选列表和下方项目身份列表重复展示相同账号；候选被保留后仍在两个区域出现。
3. Grok 的完整英文证据直接进入主列表，导致账号行高度不可控，也挤压置信度、身份操作和删除操作。
4. 项目身份、生态账号发布 CA、生态账号互动三种语义虽然已经正确拆分，但所有控件同时展开，视觉上仍像一个连续的大表单。
5. 右侧草稿栏只有进度和代币摘要，没有独立决策价值；桌面端浪费空间，移动端又被直接隐藏，说明它不是必要结构。
6. 当前页面依赖多层边框和区块容器区分层级，内容增加后形成明显的功能堆叠感。

## 2. 收敛原则

1. 一个信息只出现一次：步骤只在顶部显示，项目账号只在候选/身份列表显示。
2. 主流程只展示决策信息：账号、角色、置信度和一行关联摘要；完整证据进入详情抽屉。
3. 身份与触发严格分区：项目身份不触发交易，交易触发只由两个独立规则承担。
4. 默认收起未启用能力：两个触发规则可分别启用、同时启用或全部关闭，不要求二选一。
5. 保持现有四步业务流程和后端 payload，不因 UI 重构新增第二套状态或 API。
6. 桌面和移动端使用同一 DOM 语义，通过布局重排适配，不制作另一套移动页面。

## 3. 新页面结构

### 3.1 页面级结构

```text
页面标题 / 返回 / 快速投研
四步横向进度条
当前代币紧凑摘要
当前步骤的单列任务区
固定底部操作栏
按需出现的证据详情抽屉
```

删除现有左侧 `p16-step-rail` 和右侧 `p16-draft-aside`。工作区最大内容宽度收敛到约 1120px，表单获得完整横向空间。

### 3.2 步骤 2：X 触发账号

步骤 2 只保留两个一级任务：

1. **项目身份**
   - 单一账号列表同时承担 Grok 候选审核和已选身份展示。
   - 复选框表示是否保留为项目身份，不再生成第二份已选列表。
   - 主行显示 `@handle / 显示名 / 角色 / 置信度 / 一行关联摘要`。
   - 详情按钮打开右侧抽屉，显示完整 Grok 说明、来源、证据和核验状态。
   - 删除按钮对已核验、待确认候选一视同仁；置信度不再控制删除能力。
   - 手工账号使用同一列表新增，不创建新的展示结构。

2. **交易触发**
   - 规则 A：生态账号自己发布完整 CA。
   - 规则 B：生态账号与项目账号互动。
   - 两条规则各有独立开关，可单独启用、同时启用或全部关闭。
   - 未启用规则只显示标题、状态和开关；启用后才展开账号、事件和已有规则。
   - 两条规则统一复用同一个生态账号选择器，支持最近使用、生态账号库、输入搜索和手工账号。
   - 账号建议下拉继续支持关闭按钮、`Esc` 和点击外部关闭；互动规则必须提供明确的“添加关系”和已选关系行。
   - 输入框下方常驻最多 3 个快捷账号，按“当前链标签优先、跨链其次、权重降序”生成；`x_kol_accounts` 当前没有最近使用字段，因此正式页面不得伪装成“最近使用”。
   - 完整账号库使用挂载到页面根节点的浮层（React Portal），根据视口空间自动向上或向下展开，最多显示 6 行后内部滚动，不能被工作区、规则容器或底部操作栏裁剪。
   - 完整账号库必须展示匹配结果总数和所有匹配账号，不能再以 3 个演示账号代替账号库。
   - 第一层分类只使用 KOL 已有的生态标签：`SOL / BSC / BASE / ETH / ROBINHOOD / 跨链`，并提供 `全部 / 未分类` 虚拟筛选；同一账号可拥有多个生态标签。
   - 账号角色、机构和人物说明只作为行内备注展示，不作为第一层筛选，也不能把快速投研产生的项目账号候选混入生态 KOL 库。
   - 账号行统一显示 `@handle / 名称或备注 / 生态标签 / 权重`；权重只影响排序，不影响交易金额和触发优先级。
   - 生态互动的项目账号选项只来自已保留的项目身份、编辑态历史互动目标和已存在关系；未确认 Grok 候选不能被静默转为交易目标。
   - 规则开关关闭时会移除该规则在当前草稿中的配置：关闭“发布完整 CA”只移除 `source_kind=ecosystem`，必须保留只读 `launch` 来源；关闭“生态互动”移除关系和不再被引用的 `interaction_target`，不删除项目身份。

### 3.3 其他步骤

1. 代币与模板：链、CA、自动补全结果和配置来源保持在一个紧凑表单中。
2. 资金与离场：资金参数和常用离场策略先展示，完整高级策略按需展开。
3. 确认保存：只展示最终差异、Watch 影响和提交结果，不重复整份表单。

## 4. 视觉标准

1. 继续使用 XBOT 的中性深色工作台，不引入营销式布局、渐变背景或装饰图形。
2. 页面只保留一个外围工作区边界；内部用分隔线和留白建立层级，减少卡片套卡片。
3. 区块标题控制在 14-16px，账号和按钮控制在 12-14px，不使用夸张大字号。
4. 所有工具动作使用 Lucide 图标；删除、详情、关闭使用图标按钮和 Tooltip。
5. 卡片和控件圆角不超过 6px。
6. 长 CA、英文账号和证据使用省略、换行或独立滚动容器，不能扩大固定格式控件。
7. 已核验使用绿色，待确认使用琥珀色，身份使用青色，交易触发使用绿色；颜色只表达状态，不装饰页面。

## 5. 响应式标准

1. `>= 1100px`：四步横向显示，候选行保持表格式扫描。
2. `720px - 1099px`：隐藏全局侧栏后仍保持单列工作区，步骤标题允许缩短。
3. `< 720px`：步骤栏横向滚动；候选账号占整行，角色和操作进入第二行；规则输入垂直排列。
4. 详情抽屉桌面宽度不超过 420px，移动端覆盖内容区但保留明确关闭按钮。
5. `390x844` 验收必须满足 `scrollWidth <= innerWidth`，任何按钮、下拉和证据文本不得越界。

## 6. 正式实施范围

正式页面获批后，改动应限定为：

1. 重构 `WhitelistWorkspace.tsx` 的工作区骨架和顶部步骤栏。
2. 重构 `AccountRulesStep.tsx` 的单一候选/身份列表、证据抽屉和独立触发规则。
3. 为已知 CA 白名单增加独立的 `p162-*` 工作区样式；`p16-workspace-grid`、`p16-step-rail` 和 `p16-draft-aside` 仍被未发币监控复用，不能全局删除或改变其行为。
4. 复用现有 `candidates`、`project_accounts`、`direct_sources`、`relations` 和回调，不改 API payload。
5. 删除正式页面不再引用的旧侧栏 CSS；不删除测试、研究证据或后端数据字段。

## 7. 验收清单

- [x] 桌面端只存在一套步骤进度。
- [x] 同一项目账号在主流程只出现一次。
- [x] 完整 Grok 证据不再撑高主列表，可在抽屉完整查看。
- [x] 已核验和待确认候选都能删除。
- [x] 两种生态触发规则可独立开关且互不覆盖。
- [x] 下拉菜单可通过按钮、`Esc` 和点击外部关闭。
- [x] 四步前进、返回、校验和草稿状态保持原有行为。
- [x] API payload、Watch Impact、保存与合并契约不变。
- [x] 桌面、平板和 `390x844` 无溢出、重叠或操作遮挡。
- [x] 前端 lint/build、关键 DOM 交互和相关后端契约测试全部通过。

## 8. 非目标

1. 本方案不修改白名单匹配、交易触发、Watch 去重或 6551 同步逻辑。
2. 本方案不新增配置项、后端表、API 或另一套白名单创建路径。
3. HTML 预览使用静态示例数据，只用于审核信息架构和交互，不会保存任何真实数据。
